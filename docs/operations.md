# PhotoBook 本地运维与故障处理

## 1. 日常行为

- 未配置 R2：帖子完成本地落库即成功。
- 已配置 R2：本地成功后尝试一次有界上传；失败保留待同步状态并停止前台服务。
- App 启动、回到前台、用户手动刷新和网络恢复时可以继续同步。
- 分批拉取未完成时自动续跑；R2 读取或预览下载失败时显示最近错误并由 WorkManager 退避重试。
- 前台服务只在有抓取或用户主动同步时运行，不常驻轮询。

## 2. 常见失败

### Instagram 要求登录

每个任务先匿名访问。匿名元数据响应结构有效但无法确认帖子状态，或 Instagram 明确要求登录时，App 会在任务取消检查后使用有效 Session 探测一次 authenticated media-info，不再依赖特定 GraphQL 错误指纹。任务显示“需要登录以确认帖子状态”时，可在 Instagram 设置页完成官方网页登录，或粘贴完整 Cookie 登录后重试；显示“私密账号帖子不支持”表示登录结果已确认发布账号为私密；显示“登录后仍不可访问”表示 Instagram 登录态没有返回帖子，可能已经删除、当前账号无权访问，或存在地区/年龄限制；显示“Instagram 接口暂不兼容”表示平台返回结构已变化，需要检查 PhotoBook 更新。断网、超时和限流只自动重试，明确 404 和无法理解的响应不会启用 Session。

设置页显示“登录已失效”时需要重新登录。手动 Cookie 登录要粘贴完整 Cookie Header，App 会在线验证并在成功后显示实际用户名；输入内容提交即清空，验证失败不会覆盖旧 Session。会话可用时可点击“复制Cookie”将 Cookie Header 写入系统剪贴板；该内容等同登录凭证，应立即粘贴到用户信任的目标，App 进程存活时会在 60 秒后清理仍未被替换的该份内容。清除登录只删除本机会话，不影响已归档帖子。私密帖子始终拒绝归档，即使当前账号能够查看。

### 任务列表

首页右上角任务列表展示进行中、失败和已取消的帖子归档任务，长按任务项可复制当初分享的链接。进行中任务显示当前解析、下载、保存或“正在取消”阶段；等待自动重试时同时显示最近一次失败原因。排队任务取消后立即进入“已取消”；运行中任务先显示“正在取消”，Instaloader 的单次网络请求超时为 30 秒，同步解析函数返回后 App 完成新文件回滚和临时目录清理，再进入“已取消”。正在取消期间不能重复取消、重试或删除，也不会继续读取 Instagram Session、发起认证重试、下载或提交。失败和已取消任务可重试或删除，需要登录的任务先进入 Instagram 登录设置页。删除任务记录前需要确认，且不会删除已经归档的帖子、媒体或任何 R2 对象；活动任务不能直接删除，需先取消。

抓取自动重试与 R2 同步重试独立调度。取消一个等待自动重试的抓取任务会立即重算抓取恢复计划，不会触发无用的“恢复未完成帖子”通知，也不会取消 R2 重试或正在处理的其他帖子。

### 网络失败

确认手机浏览器能访问 Instagram，并检查系统 VPN 是否包含 PhotoBook。App 不控制 VPN 节点，也不会在 VPN 失败时静默绕过直连。

### R2 403

检查 endpoint、bucket、Access Key/Secret 和 token 的 bucket 范围。R2 S3 region 固定为 `auto`。更换凭证不会改变资料库身份。

### R2 同步卡在某设备

查看该设备期望的下一个 seq。只要中间操作对象缺失，客户端就必须停止该设备的推进，不能跳到更大的序号。修复缺失对象后再同步。

### 更换 R2 资料库

只更换 Access Key 不触发迁移。endpoint、bucket 或 prefix 改变时，App 会把当前可见帖子和帖子/媒体墓碑快照写入新资料库；快照保留原始实体版本，不会把旧状态伪装成新写入。本机尚未缓存的原媒体会暂时从上一个资料库恢复。迁移完成前不要再次切换资料库或清除配置。

### App 被系统停止

用户从系统“活动应用”停止或强制停止 App 时，Android 会终止整个进程，无法在后台自行恢复。重新打开 PhotoBook 后扫描 SQLite 未完成任务并继续。

### 更新失败

自动检查失败不会中断归档。用户可在设置页重新检查；下载失败会删除 `.part`，哈希、包名、版本或证书不匹配时必须重新发布正确 APK，不能绕过校验。系统提示“不允许安装未知应用”时，按页面引导为 PhotoBook 授权后返回继续安装。

## 3. 数据恢复

- 有 R2：新安装配置同一 endpoint、bucket 和 prefix 后，拉取全部设备操作，先恢复元数据、头像和缩略图；原媒体在详情页按需恢复。
- 无 R2：卸载 App 或清除数据会删除 SQLite 和 App 沙盒媒体，无法恢复。
- 不要手工只复制 SQLite 而遗漏媒体目录；路径会失效。
- 项目处于开发阶段，不恢复旧格式数据。结构或同步格式变化后，卸载 App 并清空对应 R2 prefix，再从空数据开始。

## 4. 清理

- App 启动时清理超过 24 小时的 `.part` 和遗留任务目录。
- 成功或最终失败的任务目录立即清理。
- 整帖失败时，同时回滚本次新建且尚未被数据库或同步操作引用的永久媒体文件。
- 不提供按 R2 prefix 批量删除功能。
- 帖子和单媒体删除只写墓碑，不物理删除 R2 对象。
- 本地内容寻址文件只有在当前业务状态和不可变同步操作均不再引用时才能清理。
